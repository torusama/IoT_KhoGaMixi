## 1. Kết quả đạt được trong ngày

Đã xây dựng nền tảng backend, cấu hình Firebase Realtime Database thật và chạy thử thành công luồng:

```text
Simulator ESP32 → MQTT Broker → Node-RED/backend → Firebase Realtime Database
       ↑                              ↓
       └──────── Lệnh và ACK ──────────┘
```

Người dùng đã thực hành chạy các tiến trình, gửi Start/Stop, xem số đo mô phỏng và kiểm tra phiên được lưu trên Firebase. Sau khi thử nghiệm, người dùng xác nhận mọi bước đã hoàn thành tốt. API hiện tại cũng xác nhận một phiên đã kết thúc và được lưu bền.

Kết quả này xác nhận đường truyền và phần backend hoạt động với thiết bị mô phỏng. Chưa dùng kết quả đó để nghiệm thu độ chính xác cảm biến, đường cong lưng trên người hoặc hoạt động motor thật.

Backend phân biệt việc thiết bị đã STOP với việc final đã lưu bền. State retained không tự xác nhận online; timeout không tự tạo phiên mới. Summary cộng dồn không được cộng lặp, event cũ không thay revision mới, dữ liệu đến muộn được giữ đúng danh tính phiên.

Đường nhận telemetry dùng thông tin phiên nhỏ có cache giới hạn, tránh đọc lại toàn bộ lịch sử cho mỗi gói. Queue có giới hạn; dữ liệu trực tiếp có thể được bỏ qua khi chịu tải, còn summary/event/final cần retry và receipt sau lưu thành công.

## 4. Các thao tác cấu hình và chạy thực tế đã hoàn thành

### 4.1. Môi trường local

- Đã có thư viện Node.js của backend và file cấu hình local được sinh bằng `npm run configure`.
- Đã chạy broker, backend và simulator bằng ba terminal trong `D:\IoT_KhoGaMixi\backend`:

```text
npm run broker
npm start
npm run simulator
```

- Đã xác định lệnh npm phải chạy tại `backend/`, nơi có `package.json`; có thể dùng `npm --prefix ./backend ...` nếu đứng ở thư mục gốc.
- Đã kiểm tra Node-RED khởi động, nạp đúng flow và phục vụ tại `http://127.0.0.1:1880`.
- Editor đang tắt theo cấu hình; việc điều khiển thử nghiệm thực hiện qua API/PowerShell.

### 4.2. Firebase thật

- Đã tạo và cấu hình Realtime Database cho project **iot-khogamixi**; đã được hướng dẫn chọn locked mode phù hợp với backend Admin SDK. Chưa kiểm tra lại rules đang triển khai trên Console trong lần lập nhật ký này.
- Đã cấu hình backend dùng Firebase thay cho file local, với database URL:

```text
https://iot-khogamixi-default-rtdb.asia-southeast1.firebasedatabase.app/
```

- Đã thiết lập đường dẫn service-account JSON cục bộ và xác thực backend thành công với Firebase Admin SDK.
- Emulator không được bật trong cấu hình Firebase thật đang dùng.
- `.env` và thư mục chứa key được Git bỏ qua; báo cáo này không chứa token, mật khẩu hoặc nội dung private key.

### 4.3. Git

- Đã thêm `/review/` vào `.gitignore` theo yêu cầu.
- Đã loại cấu hình local, secrets, runtime, cache và node_modules khỏi commit.
- Đã commit 54 tệp của phần kế hoạch/codebase/tài liệu/kiểm thử tại commit `8c641df`.

## 5. Bằng chứng chạy thử

### 5.1. Kiểm tra API backend

Kết quả đọc API trong lúc lập nhật ký:

| Chỉ số | Kết quả |
|---|---|
| Backend `ready` | `true` |
| Storage driver | `firebase` |
| MQTT connected | `true` |
| Protocol version | `2` |
| Project ID trong cấu hình | `iot-khogamixi` |
| Emulator trong cấu hình | Tắt |

Các lần kiểm tra thiết bị trước đó trong phiên làm việc ghi nhận `esp32_01` online, IDLE và `simulated:true`.

### 5.2. Phiên người dùng đã thực hành

Người dùng đã chạy luồng hướng dẫn: chuẩn bị Bearer header từ `.env` → gửi START → chờ applied → xem số đo → gửi STOP → kiểm tra trạng thái lưu phiên/Firebase.

API lịch sử xác nhận:

| Trường | Giá trị |
|---|---|
| Device ID | `esp32_01` |
| Session ID | `ses_1794411571685_c1611bdaefc8477a` |
| Mode | `measurement_only` |
| Trạng thái phiên | `stopped` |
| Storage driver | `firebase` |
| Storage status | `saved` |
| Cloud status | `saved` |
| Thời gian đo hợp lệ | `34766 ms`, khoảng 34,8 giây |
| Thời gian metric theo mốc | `0 ms` |

`valid_metric_ms=0` phù hợp với phiên measurement_only. Chưa ghi nhận thử nghiệm thủ công SET_REFERENCE rồi START mode reference để nghiệm thu histogram theo mốc cá nhân.

Các kết quả dưới đây đã được chạy trong quá trình xây dựng codebase trước khi người dùng thực hành. Không quy chúng thành các phép thử phần cứng do người dùng đã thực hiện.

## 7. Công việc tiếp theo theo thứ tự ưu tiên

1. Thử SET_REFERENCE khi IDLE, chờ ACK applied/config mới, rồi START với mode reference để kiểm tra histogram và lưu mốc.
2. Thử thủ công mất kết nối/restart broker hoặc simulator, theo dõi online/stale/offline và trạng thái phiên; đối chiếu giới hạn mất dữ liệu qua reboot.
3. Hoàn thiện firmware v2 theo [device-integration.md](../docs/device-integration.md): boot/session ID, preflight, ACK, heartbeat/state, summary/event/receipt và cấu hình MQTT.
4. Kiểm tra lần lượt bốn MPU6050/TCA9548A, hướng lắp và hiệu chuẩn; triển khai ba cung, thống kê và motor trên thiết bị thật.
5. Xây dashboard từ REST/SSE/client đã có, gồm điều khiển, số đo, đường cong, histogram và lịch sử.
6. Chuẩn bị broker ESP32 truy cập được, triển khai MQTT TLS/HTTPS và thử điều khiển từ mạng khác. Broker phát triển hiện chỉ nghe loopback.
7. Tích hợp dịch vụ gửi email, tiếp tục các phép thử phần cứng/đồ gá, độ trễ, phiên dài và tiêu chí còn lại trong PLAN.

Các hạng mục chưa được xác nhận trong ngày: motor thật, sai số Pitch/đường cong, tháo/đeo lại, dashboard hoàn chỉnh, gửi email thực, Docker Compose/Mosquitto chạy thực tế và nghiệm thu truy cập Internet từ hai mạng khác nhau.
